We need to stop thinking in terms of hardcoded formatter rules only.

We need a Jurisdictional Rules Acquisition + Registry System.

Goal:
Build a continuously expandable jurisdiction intelligence layer that can ingest, store, normalize, and apply physical filing/recording rules from external jurisdictions without disrupting the existing doctrine ecosystem.

This is additive only.

Do not alter:
- doctrine engines
- tribal logic
- NFR systems
- intake systems
- templates
- signing/stamping systems
- audit systems
- electronic tribal court seal workflows
- existing generated documents

Nothing in this system may override or conflict with existing governing principles or previously approved implementation logic. This system only acquires, maps, normalizes, and applies external filing/recording presentation requirements.

CORE IDEA:
Separate:
1. substantive doctrine generation
FROM
2. jurisdiction-specific physical formatting/output requirements.

We are building a “jurisdiction intelligence registry.”

Create these components:

==================================================

- recorder manuals
- local court rules
- filing PDFs
- e-filing instructions

- secretary of state guides
- tax tribunal filing standards

This service extracts formatting requirements and maps them into structured rules.

All normalize into:

7. acquisition strategy
==================================================

We are NOT manually coding every jurisdiction forever.

Build:
- registry-driven rules
- expandable ingestion
- source tracking
- source validation
- source refresh timestamps

The system should eventually support:
- automatic updates
- AI-assisted extraction
- manual override
- admin review
- jurisdiction versioning

==================================================
8. architecture rule
==================================================

This system sits AFTER doctrine generation and BEFORE export/print/e-filing.

It must never:
- reinterpret legal doctrine
- alter tribal authority language
- rewrite generated legal substance
- weaken existing ecosystem behavior

It only adjusts physical filing/recording presentation requirements.
